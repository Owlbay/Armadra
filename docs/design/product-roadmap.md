# 后续规划

> 状态：目标规划（2026-09-27），各项均未开始，只定方向与先后顺序。
> 现状以 [功能预期总表](../status/feature-roadmap.md) 为准；每一部分动工前另写专项设计，登记进[文档索引](../README.md)。

四个部分按顺序推进，前一部分完成后再进入下一部分。平台线（桌面各端与服务端）与四个部分并行。

| 部分 | 主题                       | 目标用户     | 依赖           |
| ---- | -------------------------- | ------------ | -------------- |
| 一   | CLI 接入、通信与共享上下文 | 开发者       | 现有协作层     |
| 二   | ACP 接入与会话视图         | 普通用户     | 第一部分       |

| 平台 | 桌面各端与服务端优化       | 全部         | 与各部分并行   |

## 第一部分：CLI 接入、通信与共享上下文（当前优先）

在现有「终端 + Hook」模型上把六种 CLI 做完整，让它们之间能可靠地通信和共享上下文。

专项设计：[CLI 接入、通信与共享上下文](cli-collaboration.md)。

- [ ] **接入对齐**：六种 CLI 的状态通道、权限模式、resume、模型选择逐项补齐，能力缺口在界面上如实标出。
- [ ] **会话索引与成本**：会话索引从 Claude / Codex 扩到 OpenCode、Pi、OMP、Copilot，成本统计同步扩展。
- [ ] **多账号**：节点账号绑定（`credentialRef`）从只读徽标做到可选、可切换。
- [ ] **通信**：`send` / `inbox` 的投递回执、失败重试与可视化；放开「SSH 终端里的 Agent 限同一执行主机」的限制。
- [ ] **共享上下文**：连线读取覆盖转录、摘要、终端画面、文件与白板对象，每次读取可追溯来源与预算。
- [ ] **真 CLI 端到端**：重写对着 core 的真 CLI 端到端用例，六种 CLI 都跑通「启动 → 协作 → 交接」。

## 第二部分：ACP 接入与会话视图

让现有 CLI 通过 ACP（Agent Client Protocol）接入，以对话形式展示，降低普通用户的使用门槛。

- [ ] **能力核实**：逐个确认六种 CLI 的 ACP 支持（原生或适配器），不支持的继续走终端。
- [ ] **会话视图**：消息流、工具调用、权限确认卡、文件差异；同一个 Agent 可以在会话视图与终端视图之间切换。
- [ ] **输出到画板**：Agent 回复里的计划、结论、代码块、Mermaid 图可一键落成便签、白板对象或编辑器节点，保留来源链接，并能再次引用给其他 Agent。
- [ ] **普通用户入口**：新建向导、默认隐藏终端细节、常用任务模板。

设计约束：v3 曾移除 ACP 通道（[v3 契约](../contracts/v3-agent-terminal-plan.md) §5.10），原因是两套 Agent 通道会让状态、权限和会话侧栏出现两种语义。这次 ACP 只作为**同一个 Agent 的另一种展示与输入方式**，状态、权限、上下文链接与投递仍走同一套 core 语义。

## 第三部分：协调 Agent 与工作流

设计一个 Armadra 自己的协调 Agent，负责拆分任务、分派给各 CLI、汇总结果；再把协作过程沉淀为可复用的工作流。

- [ ] **协调 Agent**：Armadra 自己的 `ama`（独立仓库 [armadra-agent](https://github.com/yovinchen/armadra-agent)），作为第七个内置 Agent 跑在画布终端节点里，经宿主适配器直接调用画布动词（`open-agent`、`team`、`send`、`inbox`、上下文读取）。专项设计：[协调 Agent](coordinator-agent.md)。
- [ ] **分派与汇总**：例如让 Claude Code 审查一部分代码、Codex 审查另一部分，协调 Agent 收齐结论后汇总到画板。
- [ ] **人在回路**：关键步骤（合并、推送、破坏性操作）停下来等人确认。
- [ ] **工作流录入**：把一次完成的协作保存为工作流模板，包括角色、CLI、提示词、连线、依赖顺序、worktree 与审查步骤。
- [ ] **一键复用**：工作流按参数（仓库、分支、范围）重新运行，也可挂到后台自动化上定时执行。
- [ ] **执行记录**：每次运行的分派、产出与审查结论可回看、可对比。

## 平台线：桌面各端与服务端优化

与四个部分并行推进，按下列顺序：

1. [ ] **Gateway**：桌面端开启「对外服务」，把本机 core 经服务器壳同样的 TLS、设备配对与可撤销会话暴露出去，手机与其他设备扫码即可访问。分进程时代由 Go Host 承担的这项能力在 TS core 里尚未恢复。
2. [ ] **移动网页**：在现有焦点页、底部导航、软键盘工具条的基础上补齐手机与平板的交互细节。
3. [ ] **手机 / 平板应用**：编译原生 App（iOS、iPadOS、Android），作为客户端连接 Gateway 或服务器，并接入推送通知。
4. [ ] **桌面三平台**：Windows 真机验收、签名发布与自动更新、Linux 打包。
5. [ ] **服务端**：部署文档与容器镜像、性能与资源占用、多执行主机管理。

## 第四部分：多人协同

一块画板可以邀请多人一起交流和工作；部署到服务器后，外部成员也能协同。

- [ ] **画板协同**：从现在的编辑租约（同一时刻一人写）演进到多人实时编辑，显示成员光标与选区，支持评论与讨论。
- [ ] **Agent 权限**：区分「可操作画布」与「可驱动他人的 Agent」，审批按角色（驱动者 / 编辑者）分配。
- [ ] **登录服务**：在已有本地口令、邀请、组与按工作空间授权的基础上，接入 passkey 与 OAuth 绑定，可选 SSO。
- [ ] **安全强度**：口令强度与泄露检查、登录限流与锁定、多因素认证、会话与设备管理、审计日志。
- [ ] **公网部署**：域名与证书、反向代理、备份与升级流程，形成一份可照做的部署指南。
